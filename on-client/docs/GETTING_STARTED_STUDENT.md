# 케셰브 처음 시작하기 (학생용)

이 문서는 4차 방어전부터 무엇을 만들고, 어떤 순서로 기능을 더해 가고, 마지막에 무엇이 완성되는지 설명합니다. 개발을 처음 해 보는 사람을 기준으로 썼습니다. 수업은 학원 PC에서 진행합니다.

## 1. 완성할 앱: 회사 직원이 쓰는 보안 앱

회사 직원 알레프는 아침마다 회사 PC로 여러 업무 프로그램에 접속합니다. 이 과정에서 만드는 앱은 알레프가 켜 두고 쓰는 보안 앱입니다. 앱을 열면 알레프는 다음 내용을 한 화면에서 확인합니다.

- 지금 내 계정이 어떤 PC로 로그인돼 있고, 서버가 알려 준 그 PC의 상태가 어떤지
- 업무 프로그램 하나에 접근을 요청했을 때 서버가 허용했는지, 거부했는지, 추가 확인이 필요한지, 아직 판정을 알 수 없는지
- 최근 내 접속 기록과 나와 관련된 보안 경보
- 이상한 일이 생겼을 때 AI가 기록을 근거로 설명하는 이유와 권하는 조치

카카오톡이나 네이버의 '로그인 기기 관리' 화면, "새 기기에서 로그인했습니다" 알림을 떠올리면 됩니다. 그것을 회사 업무용으로 만든 앱입니다. 회사 전체를 감시하는 관리자 화면이 아니라, 사용자 본인의 범위(최근 기록 40건까지)만 보여 주는 앱입니다.

이 앱의 기본 이름은 **케셰브(KESHEV)**이며, ALEPH 포털에서 나만의 앱 이름으로 바꿀 수 있습니다. 파일·폴더 이름(예: `tools/start-alekov.ps1`)은 실행에 쓰는 이름이라 바꾸지 않습니다. 포털에서 이름을 바꿔도 이미 받은 프로젝트 파일과 실행 중인 앱 제목은 자동으로 바뀌지 않습니다.

## 2. 학생이 만드는 부분과 이미 있는 부분

| 구분 | 무엇인가 | 학생이 고치나 |
|---|---|---|
| 앱의 학생 담당 파일 | `student/extension.mjs`. 화면에 무엇을 어떻게 보여 줄지 정하는 부분 | 예. 단계마다 이 파일을 채웁니다 |
| 기본 제공 코드 | 화면 틀, 앱 서버, 메뉴(`public/app.js`, `src/` 아래) | 아니요 |
| 기존 서버(엔진) | 접근을 허용·차단하고 경보를 만드는 회사 시스템 | 아니요. 기본 실행에서는 연결되지 않습니다 |
| 워크벤치 | 학원 PC에서 수업용 AI와 함께 코드를 고치고, 커밋한 코드를 포털로 보내 제출을 준비하는 도구 | 도구일 뿐입니다 |
| ALEPH 과제 포털 | 단계 안내를 읽고, 제출하고, 판정 결과를 보는 곳 | 제출만 합니다 |

이 과정에는 AI가 세 가지 등장합니다. 섞어 생각하지 않도록 구분해 둡니다.

- **코딩을 돕는 AI**: 워크벤치의 수업용 AI입니다. 단계 안내의 요청문을 붙여 넣으면 코드를 고쳐 줍니다. Git 명령을 대신 실행하지는 않습니다.
- **앱 안의 설명 AI**: 17단계부터 내가 만든 앱에 붙이는 AI입니다. 사건이 생긴 이유를 설명하고 조치를 제안합니다.
- **공식 판정 AI**: 제출한 커밋의 코드를 서버에서 읽고 단계 통과 여부를 정합니다. 코드를 실행하지 않고, 단계별 공식 과제 기준과 대조해 읽어서 판단합니다.

## 3. 13~16단계: 화면이 하나씩 쌓입니다

다음 단계로 넘어가도 앞에서 만든 화면은 그대로 두고 새 칸을 더합니다.

| 단계 | 시작할 때 화면 | 이번에 만드는 것 | 끝나면 보이는 것 |
|---|---|---|---|
| 13 | 기본 문구만 있음 | 로그인한 사람·PC·접속 상태 칸 | 내 이름, 내 PC와 그 상태, 접속이 사용 중인지 끝났는지. 점검이 필요한 PC나 끝난 접속은 정상처럼 보이지 않습니다 |
| 14 | 13단계 칸 | 업무 앱 하나를 골라 접근을 요청하고 결과를 보여 주는 칸 | 허용, 거부, 추가 확인 필요, 확인 불가가 서로 다르게 보이고, 요청 자체가 실패한 경우도 따로 보입니다. 허용 결과를 앱 연결 성공으로, 추가 확인을 인증 완료로 표시하지 않습니다 |
| 15 | 13·14단계 칸 | 내 접속 기록과 보안 경보 목록 | 시간·근거·규칙·상태가 적힌 최근 40건 목록. 원하는 것만 골라 보고, 한 줄을 누르면 자세히 볼 수 있습니다 |
| 16 | 13~15단계 칸 | 문제가 생겼을 때의 안내 | 연결이 끊겼을 때, 기록이 없을 때, 아직 지원하지 않는 기능일 때 사용자가 무엇을 하면 되는지 알 수 있습니다. 다시 시도는 사용자가 직접 누릅니다 |

16단계를 마치면 로그인 상태, 접근 요청 결과, 기록, 안내가 모두 갖춰진 기본 보안 앱이 됩니다.

## 4. 17~22단계: 앱에 AI를 붙이고 완성합니다

| 단계 | 목표 |
|---|---|
| 17 | 앱을 수업용 AI와 연결하고, 연결 여부와 연결되지 않은 이유를 보여 줍니다 |
| 18 | 경보가 생긴 이유를 AI가 기록의 근거를 들어 설명하게 합니다. 근거가 없으면 지어내지 않습니다 |
| 19 | AI가 조치를 제안하면 앱 사용자가 확인하고, 서버가 실제로 처리한 결과만 화면에 보여 줍니다. 여기서 사람 확인은 앱을 쓰는 사람의 확인이며, 강사가 학생을 채점하는 것이 아닙니다 |
| 20 | 내 프로젝트가 쓰는 패키지(프로그램 부품)의 버전을 공개 취약점 정보와 대조해 보여 줍니다. 조회하지 못한 경우는 취약점이 없는 것과 구분해 표시합니다 |
| 21 | 다른 사람이 설명서만 보고 설치하고 실행할 수 있게 정리하고, 구성도를 그립니다 |
| 22 | 새 폴더에서 처음부터 설치해 지금까지 만든 기능이 그대로 동작하는지 확인하고 버전을 기록합니다 |

22단계까지 마치면 보안 앱 하나와 설명서, 구성도를 갖춘 포트폴리오가 완성됩니다.

## 5. 실제 연결, 예제, 아직 안 되는 것

- 기본으로 실행하면 기존 서버에 연결되지 않은 상태입니다. 화면에 "연결 없음"이 보이는 것이 정상이며, 학생의 실수가 아닙니다.
- `npm run demo`로 실행하면 예제 자료가 보입니다. 화면 모양을 확인하는 용도이며, 실제로 연결했다는 뜻이 아닙니다.
- 지원하는 조치 목록이 비어 있거나, AI 제안이 0건이거나, 실제 조치 처리가 아직 준비되지 않은 경우가 있습니다. 이것은 학생의 실패가 아닙니다. 화면이 그 상태를 그대로 보여 주면 됩니다.
- "확인 불가"는 정상이 아닙니다. 확인하지 못한 것을 정상이나 빈 목록처럼 보여 주지 않습니다.

## 6. 시작하는 방법

- **처음 시작하는 경우:** 워크벤치에서 새 프로젝트를 만들고, ALEPH 4차 과제 화면의 「13단계 시작 틀 받기」로 받은 압축 파일을 풀어 `on-client` 폴더를 그 프로젝트 폴더에 넣습니다. 이 프로젝트 하나로 22단계까지 진행합니다. 단계마다 새 폴더를 만들지 않습니다.
- **1~12단계에서 쓰던 프로젝트를 이어 쓰는 경우:** 기존 파일과 기록은 지우거나 덮어쓰지 않습니다. 이어받는 방법은 `docs/STARTER_UPDATE.md`와 강사 안내를 따릅니다.

어느 쪽이든 시작하기 전에 지금 상태를 커밋해 두면, 문제가 생겨도 그 시점으로 돌아갈 수 있습니다.

## 7. 실행과 제출

앱 폴더(`on-client`)의 PowerShell에서 아래 명령을 실행하고, PC 브라우저로 http://127.0.0.1:5189 를 엽니다. 실행·종료·다시 실행 방법은 `docs/STUDENT_LAUNCH_GUIDE.md`에 있습니다.

    powershell -NoProfile -ExecutionPolicy Bypass -File .\tools\start-alekov.ps1

단계마다 같은 순서를 반복합니다.

1. ALEPH 4차 과제 화면에서 해당 단계의 「단계 안내」를 읽습니다.
2. 안내의 AI 요청문을 워크벤치의 수업용 AI에 그대로 붙여 넣습니다. AI가 `student/extension.mjs`를 고칩니다.
3. 앱을 실행해 화면에 제대로 보이는지 직접 확인합니다.
4. 프로젝트 폴더에서 이번 버전을 커밋합니다. origin에는 내 GitHub 저장소 주소가 등록돼 있어야 합니다.
5. 워크벤치의 「포털 제출 준비」에서 단계를 고르고 「포털에서 제출 준비」를 누른 뒤, 열린 포털 창에서 해당 단계의 제출 버튼을 누릅니다. 공식 판정 AI가 그 커밋의 코드를 읽고 판정합니다.
6. 통과하면 다음 단계가 열립니다. 통과하지 못하면 판정 설명을 보고 고친 뒤 새로 커밋해서 다시 제출합니다.

화면이 잘 보인다고 해서 단계가 통과되는 것은 아닙니다. 통과 여부는 제출한 커밋의 코드로 판정합니다. 워크벤치의 「포털에서 제출 준비」로 제출하면 GitHub 업로드(push)는 필요하지 않습니다. 워크벤치를 거치지 않고 포털에 저장소 주소와 커밋 번호만 직접 입력하는 경우에는 그 커밋이 공개 GitHub 저장소에 올라가 있어야 합니다.

## 8. 꼭 지킬 것

- AI 키·비밀번호·토큰을 코드, 커밋, 캡처, 도움정보, 대화창에 넣지 않습니다.
- 제공된 파일(`public/app.js`, `src/` 아래)은 고치지 않습니다. 고치는 파일은 단계 안내가 지정한 파일입니다.
- 실패를 성공처럼 보이게 만들지 않습니다.
- 막히면 오류 메시지 첫 줄을 수업용 AI에 붙여 넣고 "무엇을 눌렀고, 무엇을 기대했고, 실제로 무엇이 나왔는지"를 함께 적습니다. 세 번 물어도 해결되지 않으면 강사에게 도움정보를 보여 줍니다.
