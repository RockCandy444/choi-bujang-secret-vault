# 자료 API의 신원·소유자·공지 쓰기 권한 확인

이번 변경은 API 확인과 거부 코드 기록만 추가합니다. 화면 메뉴, 판정기,
주소, 기존 자료, 학습 DB와 서버 설정은 변경하지 않았습니다. 공지 자료의
저장·수정 구현과 강사 권한 부여는 수행하지 않았습니다.

## 메모

기존 로그인 검증 도우미가 확인한 `login.userId`만 사용합니다. 기존대로
DB 조회·수정·삭제의 조건에 그 ID와 저장된 `owner_id`의 일치를 넣고,
DB에서 반환한 행의 소유자도 다시 확인한 뒤 자료를 제공합니다. 새 메모의
소유자도 서버가 정합니다. 메뉴 표시·요청의 역할·사용자 번호는 권한 근거가
아닙니다. 강사라고 주장해도 다른 사용자의 메모를 읽거나 수정할 수 없습니다.

상대·소유자 없는·존재하지 않는 메모는 모두 같은 404 `NOTE_NOT_FOUND`로
거부해 존재 여부를 구별해 주지 않습니다. DB가 다른 소유자의 행을 잘못
반환하면 502 `NOTES_UNAVAILABLE`로 거부하며 그 자료를 응답에 넣지 않습니다.
검사 전에 행을 따로 읽는 절차는 추가하지 않았으므로 기존 DB 변경 조건을
통한 소유자 제한도 유지합니다.

## 공지 쓰기 권한

먼저 기존 로그인 도우미로 인증합니다. POST·PUT·PATCH·DELETE의 인증이
성공한 뒤, Supabase Auth Admin의 `getUserById(login.userId)`로 현재 저장된
사용자 정보를 서버에서만 읽습니다. 응답의 사용자 ID가 검증된 ID와 같은지
대조하고, 서버 권한 항목 `app_metadata.aleph_permissions` 배열에
`instructor_notices.write`가 있어야 권한 확인을 통과합니다. 이 항목은 이번
API에서 정한 권한 저장 규칙이며 반 엔진의 요청 계약에 필드를 추가한 것이
아닙니다. 기존 저장 자료에 그 권한이 없으면 기본 거부합니다.

요청 본문·헤더의 `role`, 클라이언트가 바꿀 수 있는 `user_metadata`, 토큰에
남아 있는 예전 권한은 사용하지 않습니다. 저장된 권한을 요청마다 다시
읽어서 권한 회수가 다음 요청에 반영됩니다. 심판 로그인 종류를 강사 권한으로
해석하지 않습니다. 조회에 실패하거나 사용자 ID가 다르면 자료를 제공하거나
변경하지 않습니다.

Supabase는 `app_metadata`를 사용자가 수정할 수 없는 권한 저장 위치로
설명합니다. 참고: [권한 메타데이터](https://supabase.com/docs/guides/database/postgres/row-level-security),
[관리자 사용자 조회](https://supabase.com/docs/reference/javascript/auth-admin-getuserbyid).

| 요청·조건 | API 결과 |
|---|---|
| 인증된 자기 메모 GET·PUT | 기존처럼 200 |
| 인증된 B의 A 메모 접근 | 404 `NOTE_NOT_FOUND`, 자료 없음 |
| 공지 쓰기의 무로그인·잘못된 인증 | 401 `LOGIN_REQUIRED` |
| 공지 쓰기의 저장 권한 부재·사용자 불일치 | 403 `NOTICE_WRITE_NOT_ALLOWED` |
| 공지 권한 저장소 조회 오류 | 503 `NOTICE_PERMISSION_UNAVAILABLE` |
| 공지 쓰기 권한 확인 성공 | 쓰기 기능 미구현이므로 405 `METHOD_NOT_ALLOWED` |
| 인증된 공지 GET | 기존처럼 200, 빈 배열 |

새 키·권한 부여 SQL·사용자 메타데이터 변경은 필요 작업으로 실행하지
않았습니다. 실제 강사 권한 등록 여부와 운영에서의 Admin 조회는 미확인입니다.
권한 조회 코드를 공지 수정 기능의 완성으로 보고하지 않습니다.

## 짧은 거부 기록과 확인

API 오류 응답의 짧은 오류 코드를 유지하며 서버에는 다음 형식으로만
기록합니다. 사용자 번호·자료 ID·URL·메모·입력값·인증 헤더·원본 오류는
기록하지 않습니다.

```json
{"event":"api_denied","resourceId":"notes","reason":"NOTE_NOT_FOUND"}
```

실행 명령: `node --test test/notes.test.mjs`.
파일 탐색기 **test → notes.test.mjs**에서 직접 API 요청 검사를 열어 터미널
결과와 대조합니다. 검사에는 실제 계정 대신 메모리의 가상 인증·가상 DB를
사용합니다. 기존 화면에서는 **개발자 도구 → Network → 메모 요청 → Response**에
오류 코드만 있고 상대 자료가 없는지 확인합니다. 로컬 서버의 터미널에서
거부 코드 기록도 확인할 수 있습니다. 인증값은 복사하거나 출력하지 않습니다.

정상은 자기 메모 동작 유지, 거부는 상대 메모 404·권한 위조 공지 쓰기 403입니다.
권한 회수 후 같은 토큰 재요청 거부, 조회 오류의 기본 거부, 로그의 자료·비밀값
비노출도 모의 검사합니다. 운영 요청·배포·학습 DB 변경·심판 판정은 이번에
실행하지 않았습니다.
