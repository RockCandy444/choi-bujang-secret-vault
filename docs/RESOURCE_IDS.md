# 8단계 자원 ID 표시

서버가 처리 경로에 따라 자원 종류를 선택하고 모든 성공·오류 응답의
`X-Aleph-Resource-Id` 헤더에 표시합니다.

| 기존/새 경로 | 자원 ID | 개별 자료 ID |
|---|---|---|
| 기존 `/api/notes`, `/api/notes/:id` | `notes` | 기존 메모 UUID 보존 |
| 새 `/api/notices` | `instructor_notices` | 현재 빈 목록이므로 없음 |

메모의 응답 JSON·CRUD·주소·소유자 검사는 유지합니다. 공지는 기존 로그인
검증 도우미를 사용하며 로그인한 GET에 빈 배열을 반환합니다. 메모 DB를
공지로 복사하거나 수정하지 않습니다. 뒤이어 추가한 API 권한 확인에서는
무로그인·잘못된 인증은 401, 공지 쓰기 권한 부재는 403, 권한 조회 실패는
503으로 거부합니다. 권한이 확인돼도 쓰기 기능이 없으므로 405입니다.
자세한 확인 절차는 [API_RESOURCE_CHECKS.md](API_RESOURCE_CHECKS.md)에 있습니다.

브라우저의 헤더·쿼리·본문에 자원 ID를 넣어도 서버의 선택을 바꾸지
못합니다. 이 ID는 자원 종류이며 사용자 역할이나 접근 허가가 아닙니다.
판정기 계약에 새 필드를 추가하지 않았습니다. 뒤이어 추가한 경로별
판정 규칙과 소유권·강사 권한 연결의 한계는 [ZONE_RULES.md](ZONE_RULES.md)에
기록했습니다. 운영 허용 경로는 변경하지 않았습니다.

로컬 검사: `node --test test/notes.test.mjs`.
앱 실행: `.\local-only\start-dev.cmd`.
기존 화면에서 로그인하고 개발자 도구의 **Network → /api/notes 요청 →
Headers → Response Headers**에서 `X-Aleph-Resource-Id: notes`를 확인합니다.
같은 출처의 `/api/notices`는 무로그인 상태로 주소창에서 열어도 401 응답의
헤더에서 `instructor_notices`를 확인할 수 있습니다. 주소창 이동은 앱이
메모리에 보관하는 접근 인증을 전달하지 않으므로 로그인 GET 성공 검사는
위 로컬 검사의 가상 인증 요청으로 확인합니다. 인증값을 복사하지 않습니다.

로컬 검사는 운영 배포·심판 판정의 증거가 아닙니다. 화면 메뉴는 변경하지
않았습니다.
