# 케셰브 최종 제품 설명서 (21·22단계 기준, starter 0.2.9)

이 문서는 학생이 21단계 설명서와 구성도를 쓸 때, 그리고 22단계 새 환경 실행을 기록할 때 기준으로 삼는 **제공 기준 설명**입니다. 학생 성취나 운영 도입을 뜻하지 않습니다. 학생 설명서는 이 문서를 베끼지 말고, 자기 프로젝트에서 직접 확인한 내용으로 씁니다. 학생이 이미 쓴 자기 설명서는 이 문서로 덮어쓰지 않습니다.

## 1. 케셰브는 무엇인가

케셰브는 4~6차 방어전에서 만드는 ZTNA·XDR 보안 Agent 앱의 기본 이름입니다. 포털에서 정한 내 앱 이름이 있으면 그 이름으로 부릅니다. 내 PC 에서 실행하며 세 화면을 가집니다.

- **보호 현황**: 로그인·기기·세션 상태, 알림, 계정 연결 확인, AI 연결, 설치 패키지 취약점 조회, 도움정보
- **업무 앱**: 앱별 접속 요청과 판정(허용·거부·추가 확인·확인 불가)
- **보안 기록**: 내 접속 기록과 저장된 XDR 경보, AI 사건 설명, 조치 준비와 결과

판정·탐지는 기존 엔진(SDP 서버)이 합니다. 앱은 판정·기록을 표시하며 AI 설명을 요청합니다. 사람 확인 조치의 요청·결과 처리 틀은 있으나, 현재 SDP 본인 기록의 supportedActions 는 비어 있고 실제 원천 집행 연결은 미완료입니다. AI 는 설명하고 제안만 합니다.

| 구성 | 하는 일 | 하지 않는 일 |
|---|---|---|
| **ALEPH** | 단계 안내, 제출 접수, 자동 확인 결과, 진도·반 순위 | 학생 PC의 파일을 바꾸지 않음 |
| **PC Workbench 작업 폴더** | 학생 프로젝트가 있는 곳, 개발·실행·문제 해결 | 앱 실행 중 계속 켜 둘 필요 없음 |
| **케셰브(보안 Agent 앱, `on-client`)** | 보호 현황·업무 앱·보안 기록 화면, AI 설명 요청, 도움정보 | 판정·탐지·집행을 스스로 하지 않음 |
| **기존 엔진** | 접속 판정, XDR 탐지, 조치 집행 | AI 결과로 판정을 바꾸지 않음 |
| **CLCO(AI 게이트)** | 앱 권한, 반 공동 사용량, AI 공급사 연결, 원본 키 관리 | 학생 프로젝트를 저장하지 않음 |

## 2. 구성도

구성도는 [PRODUCT_OVERVIEW.md](PRODUCT_OVERVIEW.md)의 그림을 그대로 씁니다.

- AI 회사의 원본 열쇠는 게이트에만 있습니다. 앱과 브라우저에는 없습니다.
- 학생 설명서의 구성도에는 상자마다 내 프로젝트의 실제 파일이나 주소를 하나씩 적습니다. 예: 앱 서버는 `on-client/src/server.mjs`, 학생 표시는 `on-client/student/extension.mjs`.

## 3. 설치·실행·종료

1. Node.js 22~24 를 준비합니다(수업·검사 기준 24.19.0).
2. 앱 폴더(`on-client`)에서 PowerShell 을 엽니다.
3. 실행: `powershell -NoProfile -ExecutionPolicy Bypass -File .\tools\start-alekov.ps1`
4. 운영자가 설정 파일을 안내했다면 `-NativeHostConfig "<경로>"`(계정 연결·AI), `-SdpHostConfig "<경로>"`(SDP 연결)를 붙입니다.
5. 브라우저에서 `http://127.0.0.1:5189/` 를 엽니다. 포트를 바꿨다면 그 포트로 엽니다.
6. 끄기는 실행 창에서 `Ctrl+C` 입니다.

- 실행 도구가 없는 옛 배포본은 `npm start` 를 씁니다.
- 기본 실행은 연결 없음 상태이고, `-Demo` 는 예제 자료입니다. 둘 다 실제 연결 성공이 아닙니다.
- 학생은 `.env` 에 AI 주소·열쇠·모델 값을 넣지 않습니다.

## 4. 연결 순서

1. **계정 연결 확인**: 「계정 연결 시작」 → 6자리 확인 번호 → 포털에서 같은 계정으로 확인 → 「로그인 확인 완료」 → 「현재 로그인 확인」.
2. **AI 앱 승인**: 「AI 연결 시작」 → 확인 번호와 승인 기한 → 「승인 페이지 열기」 → 포털에서 승인 → 「승인했으며 연결 확인」.
3. **AI 연결 점검**: 「현재 API 연결 점검」. 이것은 모델 목록 확인입니다. 사건 설명은 아직 실행하지 않은 상태입니다.
4. **사건 설명**: 보안 기록에서 기록을 고르고 「AI 설명 요청」.

운영자 준비(학생 계정·앱 권한 발급, 게이트 반영, 18단계 계정 대응 등록)가 끝나기 전에는 권한 준비 중이나 확인 불가가 나올 수 있습니다. 이것은 학생 잘못이 아니며, 성공으로 적지도 않습니다.

## 5. 무엇을 볼 수 있고 무엇을 볼 수 없는가

- **보안 기록**: 현재 등록 정보와 맞춰 본 내 기록 최근 40건입니다. 더 있으면 전체 건수와 생략 건수가 함께 표시됩니다. 전체 로그나 다른 사람 기록이 아닙니다.
- **XDR 경보**: 서버가 이미 저장한 경보만 보입니다. 화면을 열 때 새로 탐지하지 않습니다.
- **등록 기기**: 내 이름으로 등록되고 회수되지 않은 기기 100개까지, 지금 기기가 먼저입니다.
- **세션**: 지금 검증된 연결 하나입니다.
- **상태 값**: 지난 세션·기기의 상태와 서버가 모르는 값은 확인 불가로 보입니다. 확인 불가는 정상도 안전도 아닙니다.
- **조치**: 지금 기록에는 원천이 지원하는 조치가 없습니다. AI 제안은 0개, 조치 준비 버튼은 없는 것이 정상입니다. 19단계의 현재 내부 자동 확인은 시험용 원천으로 화면이 제안·사람 확인·ACK·효과 관측을 구분하는지 보는 학습 계약이며, 실제 학생의 SDP 권한·대상·집행·결과 재조회 연결을 인정하지 않습니다. 실제 원천 집행 연결과 같은 학생·프로젝트·대상의 실행 결과 확인은 전체 완료 조건에 계속 남아 있으며 지금 미완료입니다.
- **취약점 조회**: 프로젝트의 package-lock.json 과 운영자가 허용한 공개 패키지만 OSV 로 조회합니다. 조회 실패와 미조회는 취약점 없음이 아닙니다.

## 6. 비밀과 보존

- 브라우저에 열쇠·토큰을 입력하는 칸이 없습니다. 설정 파일·인증서는 프로젝트·Git·제출물 밖에 둡니다.
- 도움정보에는 요청 식별자·구성요소·버전·확인 시각·엔진 상태와 안전한 오류 코드 등 점검용 값이 들어갑니다. 표시된 내용을 직접 확인한 뒤 필요한 범위만 복사해 전달합니다. 비밀값이나 설정 파일 원문은 보내지 않습니다.
- 제공 파일 업데이트는 운영자가 합니다. 학생이 고친 파일과 `student/` 파일은 덮어쓰지 않고 보존합니다. 업데이트 전에 커밋합니다.

## 7. 실패를 만났을 때

- 실행 도구 메시지, 계정 연결·AI 앱 승인·AI 점검·기록 조회 오류 코드별 원인과 할 일은 [CONNECTION_TROUBLESHOOT.md](CONNECTION_TROUBLESHOOT.md)를 봅니다.
- 원칙은 세 가지입니다. 자동으로 다시 시도하지 않습니다. 확인 불가를 성공으로 보지 않습니다. 작업 폴더를 지우고 새로 만들지 않습니다.

## 8. 22단계 새 환경 실행 기록

새 빈 폴더에 저장소를 내려받아 위 3장대로 실행한 뒤, 아래를 차례로 확인해 재현됨·재현 안 됨·연결 없음·확인 불가로 적습니다.

1. 내 정보·기기·세션과 다시 불러오기(13)
2. 접속 판정 네 가지와 요청 실패 구분(14)
3. 기록 목록·걸러 보기·상세(15)
4. 오류·빈 화면·다시 시도·도움정보·미지원 조치(16)
5. AI 연결 상태(17)와 근거 있는 설명(18)
6. 조치 제안과 처리 결과 구분(19)
7. 패키지·취약점 대조(20)
8. 설명서대로 실행(21)

- 끄고 다시 켠 뒤에도 같은지 봅니다. 기존 폴더와 이전 기록은 그대로 둡니다.
- 예제·연결 없음 결과를 재현됨으로 적지 않고, 기다림(UNV) 항목을 완료로 적지 않습니다.
- 확인한 범위를 먼저 적고, 미완료 항목이 있으면 검증 중인 버전으로 기록합니다. 19단계 실제 실행 연결과 22단계의 같은 최종 소스 누적 재현·공식 접수 연결까지 완료·수용된 경우에만 v1.0 으로 표시합니다. 서로 다른 시험 소스로 따로 통과한 결과를 합쳐 같은 최종 소스의 완료로 세지 않습니다.
