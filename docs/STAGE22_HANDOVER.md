## 이동할 파일과 새 환경의 절차

Git 추적 파일 전체를 해당 커밋에서 받는다. 특히 `on-client/student/`,
`on-client/src/`, `on-client/public/`, `on-client/vendor/`, `on-client/tools/`,
`on-client/package.json`, 제공 문서와 학생 문서가 필요하다. 루트 메모 앱의
파일도 보존하되 Agent 실행에 루트 `npm run build`나 `npm run bundle`을 쓰지 않는다.
이 앱에는 외부 npm 의존성과 lockfile이 없어 Agent용 `npm install`은 필요 없다.
루트 메모 앱 의존성 설치·배포·DB 복원은 이번 새 환경 재현 범위가 아니다.

아래는 새 PC에서 사용하는 순서다. `<...>`는 본인의 실제 경로·최종 커밋으로
바꾸며 빈 폴더를 사용한다. 미전송 커밋은 원래 로컬 저장소에서 복제한다.

```powershell
git clone --branch codex/step13-identity https://github.com/RockCandy444/choi-bujang-secret-vault.git <새폴더>
Set-Location -LiteralPath <새폴더>
git switch --detach <제출할40자리커밋>
git rev-parse HEAD
git rev-parse HEAD:on-client
git status --short
node --version
npm.cmd --version
git --version
npm.cmd --prefix .\on-client run check
powershell -NoProfile -ExecutionPolicy Bypass -File .\on-client\tools\start-alekov.ps1 -NoNativeHost -Port 5192
```

이번에는 공개 원격에서 새로 내려받은 것으로 기록하지 않고
`git clone --local --no-hardlinks --single-branch --branch codex/step13-identity <원래저장소> <새폴더>`를
사용했다. 새 복제본이므로 비추적 비밀 설정은 따라오지 않는다. Node 기준은
24.19.0이며 이번 실제 환경은 Windows, PowerShell 7.6.5 및 제공 실행기의
Windows PowerShell 5.1, Node v24.21.0, npm 11.19.0, Git 2.55.0.windows.5다.
기준 Node 버전·새 PC 설치·다른 OS 재현은 미확인이다.

1. 원래 폴더의 `git status --short`와 기록이 보존됐는지 먼저 확인한다.
2. 새 복제본의 HEAD·on-client 트리를 확인하고 문법 검사 종료 코드 0을 확인한다.
3. 실행 후 `http://127.0.0.1:5192/`의 「보호 현황」을 연다. 연결 설정이
   없으므로 「연결 없음」이 정상이다. 도움정보·설치 패키지 조회를 수동으로 누른다.
4. 「업무 앱」의 선택 전, 「보안 기록」의 연결 없음·설명 선택 전·조치 idle을 확인한다.
5. 실행한 창의 Ctrl+C로 종료하고 HTTP가 응답하지 않는지 확인한 뒤 같은
   명령으로 재실행한다. `-Background`를 썼다면 출력된 **본인 실행 PID**의
   경로를 확인하고 그 프로세스만 종료한다. 다른 앱·모든 node를 종료하지 않는다.

설정 견본은 `on-client/.env.example`이다. 비밀 없는 포트·미설정 값만
참고하며 `.env` 자동 로드를 가정하지 않는다. `ON_PORT` 기본값 5189 대신
이번에는 제공 `-Port 5192`를 사용했다. 개인 절대경로는 실행에 필수인 상수가
아니며 복제 위치와 포트는 바꿀 수 있다. 계정/SDP 설정은 새 환경의 공식
연결 절차로 준비한다. 원래 개인 보관소·자격을 새 경로에 무작정 복사하지 않는다.

## 기존 설정·지원 범위와 제출

`aleph.config.json`의 step=12는 기존 메모 앱의 단계다. 22단계 표기 때문에
바꾸지 않는다. repoUrl/origin, 기존 배포 주소, 로그인 발급자·대상·JWKS,
원본 API, 7개 허용 경로·/api/restore는 기존 소스와 대조해 보존한다.
RULE_IDS 여섯 개는 실제 판정 분기에 대응한다. judgeIssuer는 운영 설정
그대로다. 이번 재배포·배포 로그인·운영 DB 점검은 미실행이다.

원문 확인, demo/모의 데이터, 보조 도구의 실제 로컬 실행, 학생 독립 재현,
서버 AI 원문 판정은 서로 다른 근거다. 포털의 21단계 통과는 이번 최종
커밋의 새 환경 실행 인증이 아니다. 22단계 원문 검토 통과도 운영 인증이나
v1.0 자동 인증이 아니다. 실제 집행·외부 연결 등 미완료 항목을 남긴다.

README와 이 문서를 같은 커밋에 저장한 뒤 최종 커밋에서 재현 기록을
대조한다. 22단계의 공식 원문 전달 도구로 프로젝트 밖 새 JSON을 만들고
저장소·40자리 커밋과 일치하는지 검사한다. 1~12단계용 `npm run bundle`은
사용하지 않는다. 비밀값·실명·메모 본문·bundle-notes.json·artifacts/submission.json은
이번 커밋과 원문 묶음에 추가하지 않는다. 과거 Git 이력은 원문 tar와 구분한다.

포털 「22단계」의 저장소 주소·커밋·JSON 선택까지가 이번 준비 범위다.
제출 버튼과 AI 판정은 별도이며, 준비만으로 접수·통과했다고 쓰지 않는다.
다음 학생 확인은 새 복제본의 「보호 현황」이 연결 없음으로 표시되는지
직접 확인하는 한 가지다. 원천 연결 없는 상태를 운영 성공으로 인정하지 않는다.
