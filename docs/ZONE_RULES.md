# 8단계 경로별 판정 규칙과 미완료 연결

## 확인한 공식 출처 (2026-10-13)

1단계 대화의 Deploy 링크에서 원본이 `ChoiTimo/aleph-defense-starter`임을
확인했습니다. [원본의 최신 요청 계약](https://github.com/ChoiTimo/aleph-defense-starter/blob/main/docs/DECIDER_REQUEST.md)도
18개 입력과 5개 응답 항목을 사용합니다. 소유 관계와 강사 역할은 없습니다.
`subjectId`는 가명 주체이며 Supabase `owner_id`와 직접 비교하지 않습니다.

[공식 시험 표본의 판정기](https://github.com/ChoiTimo/byteback-sample-pass/blob/main/src/decider.mjs)는
메모 소유자 비교를 엔진·서버 함수에 맡기고, 역할로 강사 구역을 열지
않으며 모든 쓰기를 거부합니다. 표본은 이번에 요청한 자기 메모 수정과
강사 수정 허용의 완성본이 아닙니다. 표본의 코드를 그대로 가져오지 않았습니다.

## 이번에 구현한 경로 검사

`src/decider.mjs`는 현재 계약의 사용자·기기 식별 값이 비어 있거나 잘못된
형식이면 거부합니다. 이 형식 검사가 신원을 새로 검증하는 것은 아니며,
기존 계약대로 엔진이 검증한 요청만 받는다는 전제를 유지합니다.

| 서비스·메서드·정확한 경로 | 판정기 처리 |
|---|---|
| `notes`, `GET /api/notes` | 기존 자기 목록 API로 통과 |
| `notes`, `GET /api/notes/<UUID>` | 메모 API의 소유권 검사로 통과 |
| `notes`, `PUT /api/notes/<UUID>` | 메모 API의 소유권 검사로 통과 |
| 계약·기존 연습의 `/notes/<UUID>` | 동일한 GET·PUT 경로 검사 |
| `/api/notices` 또는 `/api/notices/<UUID>`의 쓰기 | 검증된 강사 권한이 없어 모두 거부 |
| 그 외 경로·메서드·서비스, `path`와 `route` 불일치 | 거부 |

표에서 통과라고 적은 메모 요청에도 기존 등록 기기·입력 출처·복합 이상
추가 확인 규칙을 적용합니다. 추가 확인을 통과해도 잘못된 경로는 열리지
않습니다. GET·PUT 이외의 판정기 메모 요청은 기존처럼 거부합니다.
기존 API의 추가·삭제 기능과 화면 메뉴는 변경하지 않았습니다.

자료 선택은 기존 주소의 UUID 한 칸으로만 합니다. `export`, `all`, `edit`,
추가 하위 경로, 이중 슬래시, 인코딩한 경로, 쿼리·해시가 섞인 `path`는
허용하지 않습니다. `route`도 메서드와 경로 모양이 정확히 일치해야 합니다.

판정기에는 쿼리 원문이 없어서 자료 ID 쿼리와 기능 선택 쿼리를 검증해
구분할 수 없습니다. 따라서 이번 구현은 모든 비어 있지 않은 쿼리를
거부합니다. 빈 쿼리의 길이 0과 SHA-256 지문도 함께 확인합니다. ID 쿼리
선택 기능은 구현하지 않았습니다. 함수 경로를 `:id`와 같은 깊이에 새로
추가하지 않았습니다. 기존 메모·주소·자원 ID와 DB는 보존했습니다.

실제 구현 규칙은 기존 `starter.deny`, `device_registered`,
`step_up_required`와 새 `resource_route`, `notes_read_write`,
`notices_write_denied`입니다. 이유 코드는 기존 코드만 사용하고, 함수 이름·
인자와 응답 다섯 항목은 유지합니다.

## 소유권·강사 권한의 미완료 항목

판정기 단독으로는 A/B가 같은 메모 UUID를 요청할 때 소유자를 구별할
정보가 없습니다. 현재는 두 요청 모두 경로 검사를 통과할 수 있습니다.
자료를 제공하기 전 기존 메모 API가 검증된 로그인 ID와 DB의 `owner_id`를
비교해 A의 자기 GET·PUT은 처리하고, B의 A 메모 GET·PUT은 404로 거부합니다.
이 API 보호를 판정기 자체의 소유권 규칙이 완성된 것으로 보고하지 않습니다.

강사 수정 권한을 확인할 계약이 없어 일반 학생뿐 아니라 강사 공지 수정도
거부합니다. 앞 단계의 공지 API는 GET·빈 목록만 제공하며 수정·저장 기능이
없습니다. 강사 수정 허용과 공지 저장도 미완료입니다.

판정기 안의 소유권 비교에는 엔진 가명 주체와 자료 소유 관계를 연결하는
공식 서버 인터페이스가 필요합니다. 강사 허용에는 검증된 강사 권한 계약이
추가로 필요합니다. 실제 사용자 번호를 가명 값으로 추측하거나 요청에
임의의 역할·소유자 필드를 추가하지 않았습니다. 운영 엔진 집행 연결과
8단계 배포·심판 판정은 확인하지 않았습니다.

## 다시 확인

실행 명령: `npm run decider:test`.
화면에서는 파일 탐색기 **scripts → decider-test.mjs**를 열고 터미널의
경로 허용·export 거부·공지 수정 거부·쿼리 기능 선택 거부 결과와 대조합니다.
이 명령은 가상 요청 연습이며 실제 심판 판정이 아닙니다.

경로·기존 기기/추가 확인과 API 소유자 보호의 로컬 모의 검사는
`node --test test/decider-zones.test.mjs test/decider-input.test.mjs test/decider-step-up.test.mjs test/notes.test.mjs`로
확인합니다. 정상 결과는 기존 자기 메모 GET·PUT의 성공과 정확한 경로
통과, 거부 결과는 API의 상대 메모 404 및 판정기의 공지 쓰기·알 수 없는
경로·쿼리 거부입니다. 실제 운영 A/B 요청을 보낸 결과로 기록하지 않습니다.
