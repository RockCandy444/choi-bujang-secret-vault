# 헤임달 관제 대시보드 · 실행과 시연

2026-10-28 추가한 **프로젝트 폴더 실행용 완성본**입니다. 설치형 앱·운영 보안 제품 인증을 뜻하지 않습니다. 기존 13~22단계 학생 함수, 메모 앱, DB, 인증 설정과 포털 기록을 보존합니다.

## 실행

Git 최상위 `Aleph_Defense` 폴더의 PowerShell에서 실행합니다. Node.js가 필요합니다. 현재 제공 앱의 기준은 24.19.0이며, 이번 검증은 v24.21.0에서 수행했습니다. 이 앱에는 외부 npm 의존성이 없어 앱용 설치 명령은 필요 없습니다.

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\on-client\tools\start-alekov.ps1 -NoNativeHost -Port 5193
```

`http://127.0.0.1:5193/`를 엽니다. 이미 같은 앱이 켜져 있으면 중복 실행하지 말고 주소를 엽니다. 종료는 실행 창에서 `Ctrl+C`, 재실행은 같은 명령입니다. 다른 앱이 포트를 쓰면 그 앱을 강제 종료하지 말고 `-Port`와 브라우저 주소를 함께 바꿉니다. 실행 도구 없이 기본 5189 포트로 켜려면 `npm.cmd --prefix .\on-client start`도 사용할 수 있습니다.

위 명령은 계정 보관소 준비 없이 PC 조회 화면을 실행합니다. 기존 계정·AI 연결은 자동으로 시작하지 않습니다. 포장 명령, 업데이트 도구, DB 변경·복원은 필요하지 않습니다. 기존 메모 앱의 `aleph.config.json`은 step=12를 유지합니다.

## 시연할 핵심 기능 세 가지

1. **PC 리소스 실측**: CPU·메모리·시스템 디스크의 값·단위·측정 시각을 확인합니다. 다시 조회하면 새 실측을 읽습니다. 10초 이내에는 캐시를 사용하며 원래 실측 시각을 유지합니다. CPU·메모리 그래프는 실제 조회가 두 번 이상 쌓이면 추이를 표시합니다. 그래프 지표 버튼으로 CPU·메모리를 각각 켜고 끄며, 「실측 기록을 표로 보기」에서 수치를 읽습니다.
2. **네트워크·방화벽 설정 조회**: 주소가 구성된 인터페이스 수와 방화벽 프로필 설정을 확인합니다. 인터넷 통신 성공이나 방어 효과를 검증하는 기능은 아닙니다. SDP 연결은 별도 카드에 표시합니다. 기본 실행의 `SDP 미연결`은 PC 실측 실패가 아닙니다.
3. **Windows 기록·조회 이력**: 최근 24시간 System·Application 경고·오류 건수와 현재 화면 실행 중 조회 이력을 봅니다. 이 건수는 공격·침해 탐지 결과가 아닙니다. 자동 조회는 기본 꺼짐이며 선택 시 30초·1분 간격으로 화면이 보일 때만 조회합니다. 조회가 실패하면 자동 조회를 중지합니다.

「조회 범위와 사용 안내」는 키보드로 열 수 있고 `Esc`로 닫습니다. 기존 보안 기능은 사이드 메뉴 「기존 보안 Agent」 또는 `/agent`·`/index.html`에서 엽니다. 제공 화면의 보호 현황·업무 앱·보안 기록과 기존 학생 함수는 그대로입니다. 예제 모드에서도 **새 대시보드의 PC 값은 실측**이며 기존 Agent의 예제 자료와 구분합니다.

## 데이터 출처와 한계

| 항목 | 출처·범위 | 한계 |
|---|---|---|
| CPU | Node.js `os.cpus()` 전후 약 400ms의 전체 논리 CPU 시간 차이 | 작업 관리자와 측정 시점·평균 구간이 다름 |
| 메모리 | `os.totalmem() - os.freemem()` | 작업 관리자 집계 범위와 다를 수 있음 |
| 디스크 | 시스템 드라이브 `fs.statfs()` | 전체 디스크 합계가 아님. GiB는 1,024³바이트 |
| 네트워크 | `os.networkInterfaces()`의 루프백 제외 주소 구성 인터페이스 수 | VPN·가상 어댑터도 포함될 수 있음. 인터넷 접속 시험 아님 |
| 방화벽 | `Get-NetFirewallProfile`, Domain·Private·Public 설정 | 활성 프로필·실제 패킷 차단 효과를 검증하지 않음 |
| Windows 기록 | `Get-WinEvent`, 최근 24시간 레벨 2·3, 채널별 최근 최대 2,000건 | 상한 초과는 일부 집계. 본문·사용자·원격 주소 수집 없음 |
| SDP | 기존 `/api/diagnostics`의 엔진 모드 | 어댑터 설정은 실제 접속 검증과 구분 |

일반 권한으로만 읽습니다. 접근 거부·명령 제한·8.5초 조회 제한 시간을 만나면 해당 항목을 `확인 불가`로 표시합니다. 권한 상승이나 보안 설정 변경으로 해결하지 않습니다. OS가 Windows가 아니면 방화벽·이벤트는 확인 불가입니다. 다른 OS·새 PC에서의 실행은 이번에 검증하지 않았습니다.

브라우저에는 집계 값만 전달합니다. 이름·IP·MAC·이벤트 본문·토큰·키를 수집하지 않습니다. 신규 조회 경로는 외부 서비스에 요청하지 않으며, 조회 이력은 브라우저 메모리에만 남고 새로고침·종료 시 초기화됩니다. 기록을 저장하거나 AI로 전송하는 기능은 없습니다. 서버 측 캐시 10초와 동시 조회 공유로 PowerShell 중복 실행을 제한합니다.

## 정상 결과와 거부·실패 결과

- 정상: 실측 값과 단위·시각, 방화벽 3개 프로필, 읽을 수 있는 두 이벤트 채널의 집계가 표시됩니다. 한 항목을 못 읽어도 나머지 실제 값은 표시합니다.
- 정상: 기본 실행의 SDP 미연결은 별도 표시합니다. 기존 `/api/me`는 미연결일 때 503 `ENGINE_NOT_CONNECTED`이며 로그인 성공으로 바꾸지 않습니다.
- 거부: `/api/local-status`의 다른 출처 Origin·cross-site 요청은 403, 임의 쿼리는 400, 같은 출처 POST는 405입니다. 요청으로 명령·경로·조회를 선택할 수 없습니다.
- 실패: 서버를 종료한 후 「다시 조회」를 누르면 현재 카드가 확인 불가로 바뀌고 오류·다음 행동이 표시됩니다. 이전 실측은 이력으로만 남습니다. 서버를 다시 켜고 수동 재조회하면 복구됩니다.

## 이번에 확인한 근거

2026-10-28 한국시간, 이 PC에서 보조 도구가 수행했습니다. 학생이나 다른 사용자의 독립 실행으로 대신 기록하지 않습니다.

- `npm.cmd --prefix .\on-client run check`: 기존 학생 함수와 신규 JS·서버 문법 통과.
- `npm.cmd --prefix .\on-client run test:dashboard`: 로컬 자기 점검 5개 통과. 결과 정규화·미확인 보존·동시 조회/캐시·실패 후 재조회·HTTP 정상/거부와 기존 Agent 경로를 확인.
- 실제 일반 실행 환경에서 CPU·메모리·디스크·네트워크·방화벽·두 이벤트 채널 조회 성공을 확인. 샌드박스에서는 Windows 레지스트리 읽기와 localhost 접속이 차단되어 확인 불가/접속 오류가 났으며, 설정을 바꾸지 않고 일반 실행 환경에서 검증.
- 브라우저에서 실제 값, 다시 조회·실측 추이, 지표 선택, 사용 안내 열기·Esc 닫기, 자동 조회 선택, 서버 중단 시 오류·현재 값 초기화와 재실행 후 복구를 확인.
- 기존 `/agent`의 학생 신원·상태·AI 점검 전·패키지 조회 전 표시를 확인. 실제 계정·AI 요청·조치 집행은 수행하지 않음.
- 캡처는 Git 제외 경로 `local-only/dashboard/`에 보관. 이번 자기 점검은 심판 판정이 아니며 새로운 공식 제출·운영 검증이 아님.

## 제출 준비

기능 검토 후 비밀값과 포함 파일을 확인하고 변경을 커밋·push합니다. `git rev-parse HEAD`의 40자리 값과 GitHub의 같은 커밋을 대조한 뒤 포털 「과제 화면 열기 → 마무리 자료 제출」에 저장소 주소·커밋을 적습니다. `npm run package-app`이나 `npm run bundle`은 이번 완성본 제출에 사용하지 않습니다. 이번 구현 작업만으로 커밋·push·최종 제출을 마쳤다고 기록하지 않습니다.

기존 22단계 통과 커밋은 새 대시보드를 포함하지 않습니다. 새 완성본을 제출하려면 **이번 변경을 포함한 새 커밋**을 사용해야 합니다. 실제 서버 연결·AI·조치 효과·OSV 조회·다른 PC 재현은 이번 확인 범위 밖입니다.
