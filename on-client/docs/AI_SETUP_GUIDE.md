# 케셰브 AI 연결 안내

케셰브는 4~6차 방어전에서 만드는 ZTNA·XDR 보안 Agent의 기본 이름입니다. 기존 프로젝트가 있으면 보존하며 이어 쓰고, 3차를 끝내지 못했어도 시작 틀로 새 작업 폴더에서 출발할 수 있습니다. 같은 프로젝트로 13~22단계를 이어 갑니다. 학생은 먼저 **계정 연결 확인**을 마치고, 별도로 **AI 앱 승인**을 진행합니다. 주소·API 키를 직접 입력하거나 옮겨 적지 않습니다. 제공된 코드나 연결 완료 표시만으로 과제가 끝나지 않습니다.

## 학생 연결 절차 (화면)

기본 실행 방법은 [STUDENT_LAUNCH_GUIDE.md](STUDENT_LAUNCH_GUIDE.md)를 봅니다. 계정 연결에는 담당자가 준비한 native 호스트 설정이 필요합니다. 설정 파일이 안내되지 않았다면 직접 만들거나 다른 사람의 파일을 복사하지 말고 담당자에게 요청합니다.

1. 「보호 현황」의 **계정 연결 확인 (AI 앱 승인과 별도)**에서 「계정 연결 시작」을 누릅니다.
2. 「계정 확인 페이지 열기」로 포털을 열고 본인 ALEPH 계정으로 로그인합니다. 앱에 표시된 **6자리 확인 번호**를 포털에 입력해 확인합니다. 이 번호는 다음 AI 앱 승인의 확인 번호와 별개입니다.
3. 앱으로 돌아와 「로그인 확인 완료」를 누릅니다. 이어 「현재 로그인 확인」으로 계정 연결의 현재 상태를 확인합니다. 기한 만료·실패·확인 불가 상태를 연결 완료로 보지 않습니다.
4. 계정 연결이 확인되면 아래 **AI 연결**에서 「AI 연결 시작」을 누릅니다. 표시된 앱 승인 **확인 번호**와 **승인 기한**을 확인하고 「승인 페이지 열기」를 누릅니다.
5. 열린 포털의 보안 Agent AI 승인 화면에서 같은 ALEPH 계정과 확인 번호인지 확인합니다. 처음 쓰는 PC 프로젝트라면 프로젝트 등록 확인 안내를 읽고 등록·승인을 진행합니다. 이미 등록된 프로젝트는 안내에 따라 연결만 승인합니다.
6. 앱으로 돌아와 「승인했으며 연결 확인」을 누릅니다. 「연결 완료」는 앱 승인과 로컬 연결 정보 보관을 확인한 상태입니다. 모델 목록 조회나 실제 AI 응답까지 확인한 결과는 아닙니다.
7. 「연결 완료」를 확인한 뒤 **「현재 API 연결 점검」을 직접 눌러 17단계 모델 목록 조회**를 확인합니다. 목록 조회는 실제 모델 추론이나 18단계 사건 설명의 성공을 뜻하지 않습니다. 「권한 준비 중」·「확인 불가」가 나오면 완료로 보지 말고 도움정보를 확인합니다.

앱 승인 기한이 지나면 「연결 취소」 뒤 새로 시작합니다. 이미 승인했다면 「상태 다시 확인」을 먼저 누릅니다. 「연결 취소」 뒤 「취소 요청의 결과를 확인하지 못했습니다(확인 불가)」가 나오면 취소된 것이 아닙니다. 이미 승인했다면 연결이 남아 있을 수 있습니다. 먼저 「상태 다시 확인」을 한 번 눌러 서버의 현재 상태를 확인합니다. 「연결을 취소했습니다」는 서버가 취소를 확인했을 때만 나옵니다. 확인 중 취소하거나 상태 조회마저 실패했다면 결과가 확인될 때까지 취소된 것으로 보지 않습니다.

> 이 문서는 현재 화면의 진행 순서를 설명합니다. 새 native 호스트를 통한 17단계 모델 조회는 2026-10-14에 새 설치본의 로컬 PC 검사로 확인했습니다. 계정 원천은 합성이며 실제 학생 계정의 운영 연결 완료를 뜻하지 않습니다. 자동으로 다시 시도하지 않으며, 같은 요청을 반복해서 누르지 않습니다.

| 화면의 상태 코드 | 학생이 할 일 |
| --- | --- |
| `ALEKOV_CONNECT_NOT_MOUNTED`, `ALEKOV_CONNECT_UNAVAILABLE` | 이 버전에는 연결 경로가 아직 없습니다. 기다립니다. 판정·기록은 그대로 씁니다. |
| `ALEKOV_CONNECT_NETWORK` | 앱 실행 창이 켜져 있는지 확인한 뒤 다시 누릅니다. |
| `ALEKOV_CONNECT_CLIENT_TIMEOUT`, `ALEKOV_CONNECT_DEADLINE` | 「상태 다시 확인」을 한 번 누릅니다. |
| `ALEKOV_CONNECT_EXPIRED`, `ALEKOV_CONNECT_NOT_FOUND` | 새로 시작합니다. |
| `ALEKOV_CONNECT_REJECTED` | 승인한 계정이 지금 로그인과 같은지 확인한 뒤 새로 시작합니다. |
| `ALEKOV_CONNECT_CONTEXT_CHANGED`, `ALEKOV_CONNECT_CONTEXT_UNVERIFIED` | 계정·프로젝트·세션이 바뀌었습니다. 다시 로그인한 뒤 새로 시작합니다. |
| `ALEKOV_CONNECT_BUSY` | 진행 중인 요청을 취소한 뒤 다시 시작합니다. |
| `ALEKOV_CONNECT_STORAGE_UNVERIFIED`, `ALEKOV_CONNECT_OUTCOME_UNKNOWN`, `ALEKOV_CONNECT_RESPONSE_INVALID` | 연결 완료가 아닙니다. 「연결 도움정보 보기」 내용을 확인해 복사한 뒤 담당자에게 보냅니다. |

화면 문구는 위 코드마다 고정돼 있습니다(`public/ai-connect.mjs`의 `CONNECT_MESSAGES`).

학생은 PC의 Workbench 작업 폴더에서 개발합니다. CLCO는 AI 게이트 서버이며, 앱을 실행할 때 Workbench를 켜 둘 필요는 없습니다. AI 통신과 오류 처리는 Workbench의 공통 `createClcoClient` 구조를 재사용합니다. 공급사 원본 열쇠와 Workbench에 저장된 열쇠는 복사하지 않습니다. AI 원본 열쇠는 중앙에만 있습니다.

## 준비

- Node.js 24.19.0을 사용합니다. 외부 npm 의존성은 0입니다.
- 학생 프로젝트 절대 경로를 확인합니다. 기존 파일을 덮어쓰거나 지우거나 초기화하지 않습니다.
- 실행은 [STUDENT_LAUNCH_GUIDE.md](STUDENT_LAUNCH_GUIDE.md)의 실행 도구를 사용합니다. 학생 AI 연결을 위해 `.env`에 주소·열쇠·모델 값을 입력하지 않습니다.
- `npm start`는 `127.0.0.1:5189`이며 기본은 미연결입니다. `npm run demo`는 예제일 뿐 실제 연결이 아닙니다.
- 시작 틀 `package.json`의 스크립트는 `start`·`demo`·`test` 세 가지입니다. `student/extension.mjs` 문법만 따로 보려면 `node --check student/extension.mjs`를 씁니다.

## 담당자가 native 호스트 설정을 안내한 경우

담당자가 본인 작업 폴더에 맞는 설정을 준비하고 확인한 경우에만, 앱 폴더에서 아래 명령의 경로를 안내받은 **설정 파일의 실제 절대 경로**로 바꿔 실행합니다. 아래 경로는 예시입니다. 학생이 설정의 여섯 필드를 임의로 채우거나 registry·Vault를 직접 만드는 절차가 아닙니다.

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\tools\start-alekov.ps1 -NativeHostConfig "C:\AlekovPrivate\native.json"
```

SDP 개인 설정도 별도로 안내받았다면 두 옵션을 함께 지정합니다. 두 설정은 용도가 다르며 서로 대신 쓸 수 없습니다.

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\tools\start-alekov.ps1 -NativeHostConfig "C:\AlekovPrivate\native.json" -SdpHostConfig "C:\AlekovPrivate\sdp-host.json"
```

실행 도구는 각각 `--native-host-config`, `--sdp-host-config` 옵션으로 로컬 서버에 경로를 전달합니다. 설정 내용과 비밀은 화면·채팅·도움정보·Git·제출물에 넣지 않습니다. 준비 절차와 보관 경계는 담당자가 [NATIVE_HOST_CONNECTION.md](NATIVE_HOST_CONNECTION.md)와 [SDP_HOST_CONNECTION.md](SDP_HOST_CONNECTION.md)를 확인합니다. 기존 학생 파일을 초기화하거나 실패 후 남은 파일을 임의로 삭제하지 않습니다.

두 옵션을 함께 지정해도 SDP 계정·프로젝트와 ALEPH 계정·앱 프로젝트가 자동으로 같은 대상이 되는 것은 아닙니다. 서버가 켜졌다는 메시지는 로그인·앱 승인·모델 조회의 성공을 대신하지 않습니다. 연결 후에는 Workbench를 계속 켜 둘 필요가 없습니다.

## 기존 수동 서버 설정 — 담당자·개발자 전용

아래는 기존 개발 경로를 유지하기 위한 참고입니다. 학생에게 주소나 열쇠를 받아 입력하도록 안내하는 절차가 아닙니다. 담당자가 현재 학생·프로젝트·기간·권한과 신원 매핑 공급자를 확인한 별도 개발 환경에서만 사용하며, native 호스트 설정과 혼용하지 않습니다. 주소와 열쇠만 있다고 승인된 것이 아닙니다.

| 이름 | 넣는 값 |
| --- | --- |
| `ON_AI_BASE_URL` | 담당자가 알려 준 HTTPS 주소. 끝은 `/api/apps/aleph-on/v1` |
| `ON_AI_APP_KEY` | 그 앱 전용 열쇠 |
| `ON_AI_MODEL` | 담당자가 승인한 모델 ID. 앱 서버에 설정합니다 |

모델은 임의의 기본값이나 목록의 첫 항목을 고르지 않습니다. 브라우저, HTML, 소스, Git, 제출물, 도움 정보, 화면, 로그에 열쇠를 넣지 않습니다.

이 경로의 자격 설정·교체는 담당자가 처리합니다. 학생에게 Workbench 열쇠를 복사하거나 다시 발급받도록 요구하지 않습니다.

메뉴는 보호 현황, 업무 앱, 보안 기록 세 가지입니다. 제공된 표와 `student/extension.mjs`의 학생 표시는 서로 다른 자리입니다. AI는 사건 근거를 설명하고 사람이 검토할 조치를 제안합니다. 판정과 탐지, 실제 집행은 기존 엔진과 사람 확인이 맡으며 집행 경로는 준비 중입니다. AI가 실패해도 기존 판정과 기록은 따로 동작합니다. 미확인은 정상이 아닙니다.

## 20단계 공개 패키지 조회

| 이름 | 의미 |
| --- | --- |
| `ON_PROJECT_DIRECTORY` | 기존 학생 프로젝트의 절대 경로 |
| `ON_APPROVED_PUBLIC_PACKAGES` | 담당자가 공개 조회를 승인한 npm 이름 JSON 목록. 기본 `[]`이면 외부 조회는 0 |

package-lock 2 또는 3의 정확한 이름과 버전을 공식 레지스트리 공개 타르볼과 대조합니다. 승인된 항목만 고정된 OSV 쿼리 배치로 조회합니다. 권한 없이 비공개 이름을 밖으로 보내지 않고, 설치된 패키지를 바꾸지 않습니다.

보호 현황에서 수동으로 조회하고 취소할 수 있습니다. 결과는 `known_vulnerabilities`, `none_found`, `unverifiable`, `partial`, 미조회로 구분합니다. 정확한 버전, 출처, 조회 시각, lock 해시를 함께 봅니다. 다음 페이지가 실패해도 이미 찾은 내용은 지우지 않습니다. 결과가 없다는 것은 그 시각에 알려진 항목이 없다는 뜻이며, 안전하거나 침해가 없다는 뜻이 아닙니다. 보호 상한 256패키지를 넘으면 표시할 수 없습니다. 정확한 개수를 세었다고 가산되지 않습니다.

## 지금 경계

기본 실행만으로 계정 연결이나 앱 자격이 생기지 않습니다. 담당자가 준비한 호스트 설정, 현재 계정 확인, 별도 앱 승인과 권한 검증이 필요합니다. 새 native 호스트의 17단계 모델 조회는 0.2.6 새 설치본·실제 Windows 자격 저장소·로컬 CLCO 게이트웨이·PC Chrome에서 확인했습니다. 현재 계정과 유료 자격 원천은 합성이며 운영 Auth·실제 학생·유료 모델 추론은 아직 확인하지 않았습니다.

17·18 화면과 앱 게이트의 기존 로컬 PC·HTTP·사용량 원장·모의 AI 검사 결과는 새 native 경로의 완료 근거로 대체하지 않습니다. 17단계 점검은 모델 목록 접근을 확인합니다. 실제 모델 추론과 18단계 사건 설명의 근거·반환 검증은 별도입니다.

18단계에서 SDP 사건을 AI로 설명하려면 **SDP의 프로젝트별 사용자 ID·프로젝트 이름**과 **ALEPH의 canonical 학생 ID·native 프로젝트 UUID**가 같은 학생·프로젝트에 대응한다는 신뢰할 수 있는 증거가 필요합니다. 0.2.7 검토용 개발판은 별도 운영자 서명과 현재 SDP 정책에 결속한 대응 등록을 확인합니다. 새 설치본에서 실제 SDP·Windows 자격 저장소·로컬 CLCO·PC Chrome의 사건 설명 흐름을 확인했습니다. 계정·운영자 시험 승인·모델 응답에는 합성 자료를 사용했으며 실제 학생 등록·운영 연결 완료를 뜻하지 않습니다.

대응은 담당자가 양쪽 등록 근거를 확인해 승인합니다. SDP 정책키가 이 승인 권한을 자동으로 갖지 않으며, 별도로 허용한 대응 승인 공개키로 서명을 확인합니다. 학생이 대응 JSON을 작성하거나 다른 사람의 파일을 복사하는 절차가 아닙니다. 운영자는 SDP 서버에 `SDP_ALEKOV_AI_BINDINGS`와 `SDP_ALEKOV_AI_APPROVAL_KEYS`, 현재 서명 정책의 등록 파일 digest를 준비합니다. 학생 PC의 두 호스트 설정 형식은 그대로입니다.

본인 보안 기록에서 사건을 선택하고 AI 설명을 요청합니다. 앱이 사건 전송과 설명 공개 직전에 현재 SDP 접속·승인된 대응·본인 사건 근거·현재 ALEPH 계정·AI 앱 권한을 다시 확인합니다. 계정·프로젝트·정책·대응·사건 근거가 바뀌거나 확인 시간이 지나면 기존 요청을 새 계정에 붙이지 않습니다. 현재 기록을 다시 확인한 뒤 직접 새 요청을 시작합니다. 자동 재시도는 없습니다.

같은 PC에서 두 계정으로 로그인했거나 두 호스트 옵션을 함께 켰다는 이유로 동일시하지 않습니다. 대응이 확인되지 않은 사건을 AI에 보내거나 설명 성공으로 표시하지 않습니다. AI 설명은 기존 사건의 근거를 읽기 위한 도움말이며 실제 조치를 실행하지 않습니다. 조치 제안과 서버 처리 결과 확인은 19단계에서 별도로 연결합니다.

로컬 검수에서는 원천 토큰·정책·승인 대응·사건 근거가 바뀔 때 성공 공개를 막고, 취소·전체 요청 기한이 지난 응답을 버리는 경계를 확인했습니다. 원 감사의 중복 근거를 실제로 추가한 뒤 사건과 설명을 공개하지 않는 검사도 통과했습니다. 네이티브 증명만 마지막 파일 검사 중 만료되는 경계는 다른 기한과 분리하기 위해 명시적 20초 요청 설정으로 확인했으며, 기본 10초 정상 경로와 구분합니다. 이 결과는 제공된 연결 경로의 검토 근거입니다. 학생 확장 구현·단계 성취·공식 출시·실제 유료 AI 사용을 대신 증명하지 않습니다.


## 0.2.8 검토용 개발판의 변경 확인

모델 목록이 비어 있으면 `ON_AI_MODEL_LIST_EMPTY`, 같은 계정의 유효한 승인 모델 범위가 요청 중 바뀌면 `ON_AI_AUTHORIZATION_CHANGED`로 안내합니다. 빈 목록을 연결 성공으로 표시하지 않습니다. 잘못된 응답과 허용 밖 모델은 별도 응답 오류이며, 준비·권한·응답 오류를 자동 재시도하지 않습니다. 네트워크·취소·요청 기한 오류는 사용자가 상태를 확인하고 직접 재시도합니다. 이 재시도 분류의 변경 범위는 native 모델 점검입니다.

새 설치본·Windows 자격 저장소·실제 로컬 게이트웨이에서 빈/허용 밖/잘못된 모델 응답, 같은 신원의 모델 권한 변경, credential을 보존한 오래된 grant version의 403 차이를 확인했습니다. 바깥 준비 실패와 요청 기한, 소켓 취소의 공개 억제도 확인했습니다. 계정·원천 권한에는 합성 시험 자료를 사용했으며 유료 모델 호출과 운영 계정 수용은 하지 않았습니다.

제공 화면은 지원 조치나 AI 제안이 없는 경우를 정상 상태로 안내합니다. AI 해석과 원래 사건 근거를 구분하고, AI 오류가 과제 실패를 뜻하지 않음을 표시합니다. 사람 확인 기한이 지나면 이번 준비로 집행할 수 없음을 안내합니다. 이 표시 변경은 합성 HTTP 자료를 사용하는 PC 화면에서 확인했으며 실제 19단계 집행을 증명하지 않습니다. 학생 확장 원본과 전달 자료 조립은 보존했습니다.

표시 검사 원묶음은 마지막 해석 문구 확인에서 실패한 기록을 유지합니다. 검사에서 앞서 해석을 오류 화면으로 바꾼 뒤 해석 문구를 찾은 순서 문제였으며, 이미 도달한 경계를 반복하지 않고 남은 해석 문구·원본 보존 확인만 별도로 진행했습니다. 17·18 이전 완료 검사를 다시 실행하지 않았습니다.
