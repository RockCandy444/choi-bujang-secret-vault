# 10단계 제작 2: 로컬 시험 정책 복원

먼저 `npm run policy:restore`를 실행합니다. 검증이 통과하면 `review_required`
보고서의 복원 버전·대상·변경 줄 범위·메모 정책 영역·`confirmation` 값을 확인합니다.
이 첫 실행은 파일을 변경하거나 확인값을 자동 승인하지 않습니다.

방어전 **10단계 → 만들기 2: 제작 2**를 열고 터미널 보고서를 대조합니다.
실행 전 바뀔 항목을 확인한 뒤 `npm run policy:restore -- --confirm <확인값>`으로
실행합니다. 확인 후 입력이 바뀌면 새 보고서를 확인해야 합니다.

대상은 `local-only/policy-preview/trial-decider.mjs` 한 파일뿐입니다. CLI에서
운영 파일이나 다른 대상 경로를 받지 않습니다. [제작 1](POLICY_PREVIEW.md)의
Git 사본 `a446a9a`·당시 검증 기록·운영자가 확인한 침해 기록을 다시 읽습니다.
별도의 시험 정책·침해 기록은 현재 폴더에서 발견되지 않았습니다. 이를 임의로
만들지 않으며 현재 명령은 `INCIDENT_TIME_MISSING`으로 중단해야 합니다.

복원 범위는 메모 경로 함수 `noteRoute`와 메모 판정 분기 두 곳입니다.
그 밖의 공지·다른 서비스·공통 입력 검사·기기 검사·규칙 목록·기본 거부·함수
계약이 사본과 한 바이트라도 다르면 `RESTORE_OUT_OF_SCOPE`로 중단합니다.
경계가 없거나 중복·변조되면 `RESTORE_SCOPE_UNCONFIRMED`로 중단합니다.
다른 서비스 변경까지 통째로 덮어쓰는 복원은 지원하지 않습니다.
줄바꿈 차이가 이 보호 영역에 있으면 역시 중단합니다.

확인값은 버전·시험 정책 지문·사본 지문·침해 시각·검증 기록·변경 범위를
함께 식별합니다. 재검증 후 같은 값일 때만 임시 파일을 동기화하고 시험
파일을 교체합니다. 운영 `src/decider.mjs`, API, 설정, 학습 DB, XDR 로그는
변경하지 않습니다. 다른 파일·사본·침해 기록을 수정하지 않습니다.

시험 폴더의 `policy-restore-audit.jsonl`에는 본문 없이 시각·버전·대상·전후
지문·확인값과 `restore_attempt`, `restored`를 뒤에 추가합니다. 기존 줄은
삭제·덮어쓰지 않습니다. 감사 기록 쓰기에 먼저 실패하면 복원하지 않습니다.
교체 후 결과 기록에 실패한 경우는 `RESTORE_APPLIED_AUDIT_INCOMPLETE`이며
시험 파일이 이미 바뀐 상태입니다. 이 경우 감사의 시도 기록과 파일 지문을
확인해야 하며 미복원으로 해석하지 않습니다.
임시 파일·잠금 정리 실패는 `RESTORE_CLEANUP_INCOMPLETE`, 이미 교체한 뒤의
정리 실패는 `RESTORE_APPLIED_CLEANUP_INCOMPLETE`로 구분합니다.

동시 복원은 잠금 파일로 거부합니다. 잠금은 이 도구끼리만 조정하므로 실행
중 시험 파일·사본·침해 기록·감사 파일을 다른 프로그램으로 편집하지 마세요.
폴더·대상의 심볼릭 링크 및 대상·감사 파일의 하드링크는 거부합니다.
중단되거나 PC가 종료돼 잠금이 남으면 다른 복원이 진행 중인지 먼저 확인합니다.

정상 결과는 확인한 버전으로 시험 메모 정책만 돌아오고 다른 서비스와 감사
이력이 보존되는 것입니다. 확인값 불일치·입력 변경·검증 실패·범위 밖 변경·
동시 실행은 거부돼야 합니다. 이미 같은 정책이면 `no_change`이며 쓰지 않습니다.

`node --test test/policy-restore.test.mjs`는 임시 폴더의 가상 침해 기록·시험
정책만 사용합니다. 복원한 시험 정책의 정상·금지 요청은 가상 판정기로
검사합니다. B의 A 자료 접근 거부는 기존 API 소유자 검사가 담당하며
판정기 단독으로 A/B 소유자를 구분하지 않습니다. 실제 A/B 운영 확인과
심판의 10단계 복구 경로 연결은 미실행이며, 로컬 시험 파일 교체만으로
완료했다고 보고하지 않습니다. 자료 복원·운영 복구 API는 후속 제작 범위입니다.
